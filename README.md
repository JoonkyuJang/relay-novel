# Relay Novel (릴레이 소설)

A relay-novel site: people write a short story together, one line each.
Static frontend on GitHub Pages + a Supabase (Postgres) backend.

**Stage 1 (now):** technical foundation with a deliberately plain UI.
**Stage 2:** visual design, replay, likes, anthology export, branching.

## How it works

- All data lives in the private `app` schema. The browser can only call the
  functions in `public` (see `supabase/migrations/`), which enforce every rule.
- Lines form a **tree** (`parent_id`). The official story is the chain of
  `canonical` lines from the first line to `stories.head_line_id`. A unique index
  guarantees at most one official line per position.
- **Baton:** clicking "이어 쓰기" reserves the next line for a few minutes
  (`claim_baton`). Others see "누군가 쓰는 중".
- **Safeguard:** `submit_line` sends the line it continues from. If that is still
  the latest line, it is accepted. If not (or someone else holds the baton),
  the line is still saved, as a hidden **conflict** flagged for the admin.
  Each story's writes are serialized with a row lock.
- **Admin tools** never delete: "Rewind to here" / "Swap in + cut after" move
  later lines to `archived`; "Swap in, keep following" replaces one line and
  re-attaches the rest. Each can be undone the same way. Soft delete just hides.
- Live updates: clients subscribe to `public.realtime_signals` and re-fetch,
  Safety nets: a cheap version check of the watched signal keys (every 20 s without realtime,
  60 s with it; only changed keys trigger a re-fetch) and a full refresh every 2 minutes.

Login is honor-system: name + student number are stored only in the visitor's browser and
sent with each write. "둘러보기" lets people read without logging in.

## Setup (one time)

1. **Supabase → Project Settings → Integrations → GitHub**: connect this repo,
   working directory `.`, production branch `main`, *Deploy to production* on,
   automatic branching off. Pushing to `main` applies new files in `supabase/migrations/`.
2. After the first deploy, make your account an admin. In **SQL Editor** run:
   ```sql
   insert into app.admins (user_id)
   select id from auth.users where email = 'YOUR_ADMIN_EMAIL';
   ```
3. **GitHub → Settings → Pages**: deploy from branch `main`, folder `/ (root)`.
   The site is then at `https://joonkyujang.github.io/relay-novel/`.
4. Open `…/relay-novel/tests/remote/` (logged in as admin first) and run
   the concurrency self-test.

## Admin

There is no visible admin button. On the 연문회 OS login window, type the admin **email in 이름**
(the 학번 field turns into a password field) and the **password in 학번**, then 들어가기.
A wrong password shows the same message as any other login problem. The 관리 menu and the
관리자 콘솔 window appear; 관리자 나가기 inside the console signs out.

## 부가 기능 (extras)

Every extra has a switch in **관리자 콘솔 → 부가 기능** (inner tabs 바탕화면 · 낮과 밤 · 화면 보호기 ·
고양이 · 도장 · 완결 이야기 · 소리 · 숨은 재미). Changes save immediately and reach open screens live. (새 이야기 제목 필수 is also stored in extras but sits in the 설정 tab.)

- Storage: `app.settings.extras` (jsonb) merged over `app.extras_defaults()`;
  `admin_update_settings` accepts only known keys with the same JSON type. The front-end copy of the
  defaults is `js/extras/extras.js` — keep the two in sync when adding a key.
- `js/extras/`: `extras.js` (settings, event bus, Seoul time), `stamps.js` + `stamp-art.js` (도장; outlines
  generated from BM JUA), `cat.js` + `cat-sprites.js` (문냥이), `saver.js` (화면 보호기 3·6·10분),
  `daynight.js` (sky by Seoul time, real moon phase), `desk.js` (메모장, 휴지통, 마감 시계, 우클릭 메뉴,
  오늘의 첫 문장, 이 컴퓨터에 관하여), `record.js` (이야기 기록), `sound.js` + `synth.js` (all sounds synthesized with WebAudio in one retro chip palette — pulse, triangle, LFSR noise, 60 Hz steps — no files; off by default per device; the 낭독회 voice follows Korean phrase intonation),
  `fun.js` (숨은 재미 — deliberately not in 도움말), `print.js` (원고지로 인쇄), `report.js` (오류 보고 → 관리 · 기록).
  `js/views/mine.js` is 내가 쓴 줄 (click your name in the menu bar). The admin console loads on demand.
- Database: `stamps`, `counters` (cat pets, unused batons) and RPCs `toggle_stamp`, `get_story_stamps`,
  `pet_cat`, `story_cards`, `get_about`, `get_counters`, `admin_line_stamps` (migrations `20261106000000_extras.sql`,
  `20261108000000_hardening.sql`: one baton per person, stamp ownership by device, range checks).
- Live "n자 쓰는 중" uses a Realtime broadcast channel `typing:<storyId>` (numbers only, nothing stored).
- Per-device choices (sound, sky override, screen saver off, 원고지 칸, memo) live in localStorage `rn.*`.

## Starting the program (clean slate)

관리자 콘솔 → **초기화**: reset the cat counter / 휴지통, clear browser errors, stamps, the
guestbook (numbering restarts at #001), only the `[TEST]` stories left by the concurrency test,
or everything at once (전부 초기화). Destructive ones ask you to type 지우기 and download a
backup JSON first. Settings, 부가 기능 switches and admin accounts are never touched.

## Before every commit

Run `node tools/version.mjs`. It rewrites the asset block in `index.html` so every CSS/JS URL
carries a hash of its content (`?v=…`, plus an import map for the modules). After a deploy,
browsers then fetch exactly the files that changed and never mix old and new modules.
`npm test` refuses to run if you forgot.

## Changing the database

Never edit an applied migration. Add a new file
`supabase/migrations/<YYYYMMDDHHMMSS>_<name>.sql` and push.

## Local tests (development machine with PostgreSQL 16)

```
cd tests/local && npm install
npm test        # resets a local DB, applies migrations, runs run.mjs (32 checks incl. races)
npm run e2e     # browser flows with Playwright against the same local DB (desktop + phone; ONLY=<name> runs one flow)
```
`reset.sh` expects a local server on socket `/var/lib/postgresql/rn`, port 5433.
